# LINE 視窗置中助手

這個 Windows 小工具把符合條件的 LINE 視窗移到主螢幕中央，方便查看和使用 Codex 操作。它**只調整視窗位置與必要的大小**，不讀取聊天內容、不輸入文字、不傳送訊息，也不處理其他程式。

你可以把本儲存庫連結交給同事，並請他們的 Codex 依「給 Codex 的安裝指令」處理；分批傳訊要另外提供訊息和收件條件，範本在 [PROMPT.md](PROMPT.md)。

## 使用前

- Windows 電腦版 LINE 已安裝並登入；電腦處於解鎖狀態，LINE 視窗沒有最小化。
- 本專案使用 Python 3.11 以上與 [uv](https://docs.astral.sh/uv/)。專案第一次設定需下載必要依賴。
- 若要 Codex 操作 LINE，必須在同事自己的 Codex 環境中具備可用的電腦操作功能及相應權限。選擇 GPT-6.1 Terra（若帳號提供），再實際確認 Codex 能看見 LINE 視窗。模型本身不會自動開啟電腦操作功能。

Codex 執行的動作仍受它的工具能力與確認規則約束；如果無法存取或操作電腦，請依下方步驟自行執行，或處理 Codex 回報的問題。

## 自行安裝及啟動

1. 取得本儲存庫的 ZIP 並解壓縮，或以 Git 複製；進入解壓後含有 `pyproject.toml` 的專案資料夾。
2. 開啟 PowerShell，執行 `uv --version` 確認已安裝。若已有 Scoop，可先執行 `scoop search uv` 與 `scoop info uv`，確認適合後執行 `scoop install uv`；如果 Scoop 尚未安裝，請參考 [uv 官方安裝說明](https://docs.astral.sh/uv/getting-started/installation/)選擇適合的使用者範圍方案。
3. 在專案資料夾執行：

   ```powershell
   uv sync
   uv run line-window-center
   ```

   `uv sync` 會建立本專案的環境；如需取得合適的 Python 或套件，可能需要網路連線。
4. 確認出現「LINE 視窗置中助手」視窗；此時它持續監看符合條件的 LINE 視窗。
5. 使用完畢點「停止並關閉」。此工具不設定開機自動啟動。若不用了，可先關閉助手，再自行刪除下載的專案資料夾；若 uv 也不再需要，可依原安裝方式移除。

同一個 Windows 登入工作階段只允許一個助手執行；若再次啟動後沒有新視窗，請先確認是否已有助手在執行。

## 讓 Codex 分批分享訊息

1. 在 Codex 選好可用模型，確認電腦操作工具能辨識 LINE 畫面。
2. 準備訊息原文、好友名稱關鍵字及截止時間；貼上 [PROMPT.md](PROMPT.md) 中的範本並填寫資料。
3. Codex 在 Keep 筆記核對原文後，透過「分享 → 好友」搜尋符合條件的個人好友，每批最多 10 位。若搜尋結果或身份不清楚，先跳過或停止確認。
4. 每次分享前後記錄批次與狀態；若結果不明，保留待確認，不要直接重按。到達截止時間停止。已提交分享不代表對方已讀或已驗證送達。

**置中工具不會自動操作或傳訊。** 分批分享依賴 Codex 可見且可操作的 LINE 畫面、使用者提供的清楚授權，以及實際介面功能。記錄含收件人資料，應存放在使用者自己的安全位置，不要提交或公開到 GitHub。

## 限制與疑難排解

- 只辨識標準 `%LOCALAPPDATA%\LINE\bin` 目錄下的 LINE 程式視窗；非標準安裝路徑可能無法辨識。
- 不會還原最小化視窗；沒有標題且沒有擁有者的視窗、小於 200 × 150 的浮動元件及部分特殊對話框可能不會處理。
- 太大的符合條件視窗會縮小至主螢幕工作區內；工具啟動時會處理既有視窗，其後處理新出現或移出工作區的視窗。
- 將視窗置中不能保證擷取成功。若 Codex 看不到畫面，先確認電腦已解鎖、LINE 視窗可見，再檢查 Codex 的電腦操作工具與權限；無法可靠辨識時不要盲目點擊或傳送。
- 不同 Windows、LINE 或 Codex 版本及設備的實際相容性，需在各台電腦上測試。

## 驗證

在專案資料夾執行 `uv run python -m unittest discover -s tests`，可檢查日期與座標等邏輯。單元測試不能取代實際 LINE 視窗移動及 Codex 擷取測試。
